# 后续用户验证协议与空白记录

状态：**未开展；用户目前没有体验者。** 下面是待执行材料，不是已发生的访谈或测试结果。依据 [W3C 用户评估建议](https://www.w3.org/WAI/test-evaluate/involving-users/)，将用户观察与技术无障碍检查结合；小样本主要用于找问题，不支持群体效果或统计显著性结论。

## 开始前

征得参与者同意，说明是原型测试、可随时停止、测试的是产品而非个人能力。默认不录音录像、不记录姓名、联系方式、诊断或私人海报；仅使用编号及完成任务所必需的设备/辅助工具信息。参与者使用自己熟悉的工具，不要求为测试停用辅助技术。需要外部邀请、真实资料或发布时仍遵守授权边界。

先由开发者检查键盘、200% 文字缩放、桌面与移动布局；分别在实际桌面/移动读屏环境记录读出顺序、标签、焦点和状态通知。开发者走查只能叫技术检查，不能填入目标用户记录。准备可访问的任务说明，出现疲劳或障碍时暂停。

## 两类任务

| 对象 | 任务说明 | 观察依据 |
|---|---|---|
| 内容核对者 | 请把有权处理的材料整理为文字，修正预置错字，保留缺失信息，确认并交给接收者 | 是否漏掉全文错字、是否把未知编成答案、额外帮助、操作失败与耗时 |
| 接收者 | 请从结果中找出活动何时、何地、怎么报名；无法确定时说出哪些还需核实 | 对照独立人工答案；错误行动意图、是否知道未知、能否使用自己的大字/读屏工具 |

为检查相对收益，用“现有 OCR / 人工整理 + 平常的阅读工具”作基线。不同条件使用难度相近且答案独立核对的两份材料，交替先后顺序；不要让重复记忆同一答案成为产品提升。分别记录辅助说明，不能把主持人告知答案后的完成当独立完成。

角色单独观察：先自由选择角色互动或跳过，随后询问“刚才这个产品想让你做什么”“角色有没有让你分心或不舒服”“去掉角色是否影响完成任务”。不先暗示其有趣或有公益效果。点击、停留时间和喜欢角色都不直接计为任务完成。

## 报告与进入条件

先争取一组操作者与接收者完成一次使用交接，再按可获得条件扩到原计划的 3–5 人。写明人数、有效任务分母、失败与额外帮助；不把人数少改写为已经普遍有效。采用只能记录需求方实际确认，下载、确认按钮和操作者自报不算机构采用。

发现错误报名、时间地点误导或导致不能使用的障碍时，先修复再复测。没有参与者、读屏设备或实际采用时，对应表格保持未开展；本地自动化结果仍可独立交付。
