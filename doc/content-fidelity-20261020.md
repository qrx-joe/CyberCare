## 计划与边界

1. 冻结复核输入 → verify：原图、先验、原模型正文及报告哈希；主要文字单元只从调用前已冻结的转录选取，二维码目标和无法稳定辨认的小字单列不计分。允许按图面分组，但不补写先验没有的字。
2. 离线复核工具 → verify：Unicode NFC / 空白归一的文字覆盖、仅大小写差异与未定位分开；概述 / 描述使用明确引用和图面依据的开发者事后审阅，不让程序判断语义或模型给自己打分。严格核对引用与文件哈希，拒绝旧引用、伪造来源单元及覆盖旧产物。
3. 实际输出与下一决策 → verify：分别运行中文与竞赛图，保留可定位文字、额外归因、解释性描述和未评分区域。不合并材料或推理档位，不把选取的文字单元 / 主张数包装成全文准确率、用户效果或社会价值；记录具体质量缺口与下一优先项。

本节点是开发者代理的**事后复核**，已经看过历史结果，不是盲测或独立真人答案。两张材料的来源、许可与原始字节沿用既有记录；不解码 / 访问二维码，也不执行图中的浏览历史提交指令。真实模型请求上限 **0**，不改 Provider、提示词或演示配置。

文字覆盖只能证明选定字串在转录中出现，不验证语义归属、顺序、额外文字或原图事实。语义审阅由开发者代理填写，其引用定位不等于结论正确；未评分和未审阅不能记为通过。

## 工具节点

新增 `npm.cmd run evaluate:content -- --manifest <本地清单> --output <新的 .local/validation/报告.json>`。清单明确列出原图、先验、捕获正文与原报告的路径 / 哈希，以及选定文字单元和事后审阅栏位；不扫描目录、不读取 `.env`、不调用 Provider 或网络。输出只能新建，不能覆盖旧报告。再次运行须指定新的输出文件。

程序只检查先验中确有该文字、捕获输出中确有被审阅引用、依据 ID 及文件哈希。二维码或无法确认区域保留 `unscored`；仅大小写差异独列。审阅分为图面支持、图面未明示、来源不确定和解释性描述，结论来自开发者记录，不是程序读图。即使选定项没有待处理发现，`overallQuality` 仍为 `not-assessed`，不生成全文准确率或整例通过声明。

5 项定向工具检查通过，覆盖文字 / 数字 / 标点边界、未评分、来源与引用约束、输入不改写、哈希漂移、输出目录与防覆盖、错误 JSON 不回显原文；没有重跑或改变四字段评分。本工具不判断引用结论是否真实、是否穷尽所有主张，也不把未评分变成正确。
