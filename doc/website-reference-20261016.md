# acc.oozoo.cc 产品参考评估

读取日期：2026-10-16，Asia/Shanghai。用户要求读取该网站，研究可借鉴方案与内容。本轮只研究并形成建议，没有修改产品实现或线上网站。

后续执行：用户要求“开始继续优化”后，下述两个 P0 已在本地实现，见文末。研究阶段的观察和未验证项保留；P1 复制失败退路仍待实施。

## 读取范围与证据

- [首页](https://acc.oozoo.cc/) 实际标题是“无障碍急救站 · 赛博公益”，展示图片、语音与截图指导产品，没有在所读页面中发现赛事规则或资源目录。不能根据域名将其当作 ACC 官方赛事说明，也不能确认它对应当前本地仓库的哪个版本。
- 普通网页读取工具未能打开；随后通过浏览器和公开 HTTP 成功读取首页、[前端脚本](https://acc.oozoo.cc/app.js)及[样式](https://acc.oozoo.cc/style.css)，三份资源均返回 HTTP 200。
- 实际切换三类任务，逐一打开预置示例；观察了文件提示、目标输入要求、结果分区、示例身份提示和隐私说明。脚本中的示例在浏览器本地生成，不发起任务请求。
- 没有上传文件、提交 AI 请求、点击复制或反馈，没有访问后台、注册登录、调用模型、部署或改变第三方持久数据。真实服务可用性、模型效果、服务器文件删除与无障碍符合性均未验证。

## 产品定位差异先于界面取舍

参考页面向“当前遇到信息或操作困难、希望获得帮助的人”；我们的当前海报任务以“制作 / 核对公益内容的人”为直接操作者，读屏或大字阅读者为接收者，角色与短科普负责引入行动。这一用户划分仍是假设，见 [MVP 方案](mvp-plan-20261022.md)。

因此，建议把参考页的清楚表达用于我们的任务区，继续保留“角色 → 科普 → 海报小任务 → 检测确认 → 反馈”。若要改成覆盖三类问题的求助工具，需要重新决定目标用户与验证范围，不能在借鉴界面时悄悄改变方向。

## 值得学习与现有能力对照

| 参考观察 | 对我们的意义 | 当前状态 / 建议 |
|---|---|---|
| 用具体生活困难说明入口，再给出明确动作 | 让用户知道现在能做什么 | 已有单海报任务和直接进入入口；任务区可补一句输出承诺：一份可读文字、一份大字页面、一份核对记录。角色开场保持 |
| 不上传文件也能先看预置结果，清楚说明示例身份 | 在正式提交前展示产物与边界 | 我们已有合成样例，但需要经过提交与核对流程；可新增只读结果预览，明确未运行检测、不能当作本次回执 |
| 结果分开呈现原文、重点和待核实内容 | 减少用户从大段回答中找重点的负担 | 我们已有原始转录、概述、四字段、未知与引用依据，无需重建。可改善呈现顺序与未知提示的可操作性 |
| 截图指导示例限制到当前一步，之后再补新截图 | 限制一次输出过长操作链和猜测后续界面 | 作为未来截图链路的验收候选；当前不增加截图入口，不将示例当成已验证指导能力 |
| 隐私说明区分本方处理、模型供应商与反馈存储 | 数据承诺应具体到责任与保存位置 | 我们已有内存、30 分钟、删除和供应商未知说明；可精简前端表达，仍以实际实现为准 |
| 复制失败有手动选择文字的退路；结果出现后移动焦点 | 降低环境权限和读屏导航带来的操作阻碍 | 我们已有结果聚焦、状态通知、复制与导出；可补复制失败后的具体操作提示 |

页面能力的主要证据来自 [公开前端脚本](https://acc.oozoo.cc/app.js)。上述“意义”和“建议”为本项目分析，不是网站作者或用户研究给出的结论。两站都已有的能力记为保留项，不能重新包装成新增成果。

## 本轮不照搬的部分

1. **三条链路同时可点。** 会把当前单海报验证范围扩大到音频、截图及不同失败边界；仍按原方案顺延。
2. **只有生成结果加提醒的短流程。** 参考公开界面和脚本未见我们已有的逐字段确认、同版本 HTML 检测及导出门禁；不据此断言其后端不存在检查。我们继续保留这些门禁。
3. **直接采用站点隐私文案和上传上限。** 它声明服务端临时文件并标出图片 10 MB / 音频 25 MB；这是站点说明与前端检查，服务端实际执行未知。我们当前是内存处理、图片 2 MB，不随界面借鉴改变。
4. **将反馈按钮当作效果证据。** 参考脚本仅在当前页面显示选择；我们记录的是任务级自报反馈，两者都不能证明真实采用或公益效果。
5. **再次更换整站视觉。** 参考页采用米白与绿色静态卡片；我们刚统一深蓝、青色和淡紫，并按用户要求实现动态角色。可以学习信息层次，不据此再次混搭主题或移除角色。

## 研究时提出的最小采用方案

按收益与范围排序；不增加模型调用、业务 API 或第二条任务链路。

| 优先级 | 变更 | verify / 完成条件 |
|---|---|---|
| P0 | 任务区提供一键只读示例预览，并说明三类最终产物 | 不创建任务、不触发模型或检测；始终显示合成 / 未确认身份，不开放正式导出；可返回实际核对流程 |
| P0 | 未知字段增加具体核实提示，例如向活动方询问报名渠道；原图缺年份时提醒核实日期 | 保留未知原值及引用；不代填日期、地址或联系方式；修改后旧检测和确认仍失效 |
| P1 | 复制失败时说明手动选择或下载文字的办法 | 模拟剪贴板拒绝后仍能获得文字，且只提供已经确认的结果 |
| 保留 | 单链路、角色叙事、统一配色、逐项确认、检测与版本、现有反馈边界 | 原业务与浏览器回归继续通过 |

研究本轮仅创建本记录并同步协作摘要，未将上表变更实施。若继续推进，优先做两个 P0 小改并验证交互，之后仍需补真实海报与接收者使用证据，不能用界面改善代替价值验证。

## 核心判断与未知

参考页值得学习的是：降低初次理解成本、先展示产物、把不确定性放到结果中。它没有提供角色动画技术方案，也没有在所读材料中展示可信的使用效果数据。当前不能证明哪种入口更能留住用户，或哪种输出更方便接收者；这些仍需实际参与者验证。

本轮结构影响仅为文档。应用页面、角色动画、后端、Provider、契约、检测与导出均未改动，不运行与文档修改无关的业务测试。
