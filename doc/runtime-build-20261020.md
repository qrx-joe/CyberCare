# 本地演示运行版本核对

日期：2026-10-20（Asia/Shanghai）。本节点修复“磁盘已经构建新版，但旧进程被报告为新版”的诊断错误，并提供保留资料后的更新步骤。

## 复现与修改

旧 `/api/health` 每次读取磁盘 `build-info.json`，没有记录进程启动时的构建。隔离回归先启动构建 A，只将记录换成同一提交的新构建 B；旧实现随后把运行版本报成 B，测试失败。本机 4312 的进程启动时间也早于其报告的构建时间；旧进程没有运行版本能力，不能据此断言实际加载了新模板。

现在启动时保存经过白名单校验的构建记录，健康接口和配置接口分别提供：

| 字段 | 含义 |
|---|---|
| `build` | 本次进程启动时的构建记录；不能读取时为 null |
| `availableBuild` | 当前磁盘可读取的构建记录；缺失、损坏或格式不符时为 null |
| `restartRequired` | 两份有效记录不同为 true，相同为 false，任一未知为 null |
| `startedAt` | 此服务模块的启动时间 |

同一提交重新构建也比较构建时间等字段，不能只看提交号。健康接口的 `status: ok` 表示服务响应，不表示版本一致。任意构建文件内容不会整份返回，额外字段与无效记录不作为可信版本。

页面只在有差异或无法核对时显示说明；旧服务缺少该能力同样保留未知，不显示“新版已加载”。“重新核对版本”只读健康接口，不刷新页面、不删除任务、不重置草稿、不自动重启。更新说明提醒先导出所需结果、保存未提交文字，再停止旧服务并重新启动；重启仍会清空原内存任务。
