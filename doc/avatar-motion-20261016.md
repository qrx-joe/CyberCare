# 角色动态化：2026-10-16

10/20 缺素材纠偏：独立源码副本实际使用文字角色，但原界面仍称“静态参考图”、动作开和“2D 动作”。先在浏览器回归复现标签错误，再修复三种显示状态；没有帧图时动作按钮不可用、状态为关，按钮说明改为文字互动；关闭动作或减少动态时也不显示假低头和“咚”。有帧图加载成功后恢复可用动作，预设互动和海报入口继续保留。带素材的角色 / 入口相关 4 项浏览器回归通过，另核对动态、静态参考图、纯文字三种实际显示状态；帧图哈希未变，本节点外部模型请求 0。原始日志与截图仅留 `.local/validation/avatar-fallback-20261020/`。不把缺帧图时的 CSS 状态或台词当作已播放 2D 动作；干净源码交付的后续完整复核另记。

用户要求“数字人是静态的，我想把它做成动态的”。原实现只对参考图做短暂整体变换，角色的眼睛和嘴没有变化。本轮改为透明角色帧图 + Canvas 播放，背景卡片保持静止，沿用现有配色和海报闭环。

## 实际动作与边界

| 触发 | 实际行为 |
|---|---|
| 角色在可见区域，动作开启 | 轻微呼吸；每 2.8–4.6 秒自动眨眼 |
| 随机互动或任务状态台词 | 短暂切换张嘴 / 闭嘴表情，结束回到中性帧 |
| “先磕一个” | 低头与回正帧，约 0.8 秒复位，可重复触发 |
| 关闭动作、离屏、页面隐藏 | 清理表情与眨眼定时器，停在中性帧；关闭 CSS 呼吸 |
| 系统减少动态 | 停止动画并禁用开启按钮，文字互动和任务可继续 |
| 缺少或无法解码帧图 | 回退静态参考图；参考图也缺失时使用文字角色 |

这是 2D 帧动画；台词是前端预设，没有实时 AI 对话、声音、音频口型同步、3D 骨骼或实时生成视频。表情只作视觉演绎，不代表已经接通语音数字人。生成帧之间有轻微头发 / 衣物差异，动作自然度仍待用户评审；未开展目标用户测试。

## 验收步骤

1. 本机已运行服务时刷新 [Demo](http://127.0.0.1:4310/)；首次运行按 README 执行 `npm.cmd run dev`。应显示“2D 动态角色 · 本地帧动画”。
2. 在首屏停留约 5 秒，检查角色眨眼与轻微呼吸；卡片边框和背景不随角色运动。
3. 点“随机互动”观察嘴部表情；重复点“先磕一个”观察低头及复位。没有声音是当前范围内的行为。
4. 关闭角色动作后再点互动，应仅变文字；重新开启可恢复。滚动离开角色再返回，或开启系统减少动态，检查停止 / 恢复行为。
5. 进入海报合成样例，继续完成修改 → 检测 → 逐项确认 → 导出。运行 `npm.cmd test` 与 `npm.cmd run test:e2e`，实际结果见 [验证记录](validation-20261016.md)。

## 结构影响

修改 `src/web/host.ts` 管理帧播放及暂停生命周期，`index.html` 增加独立 Canvas 与说明，`style.css` 只移动角色层；`scripts/build.mjs` 读取可选本地素材。新增 `tests/browser/avatar.spec.mjs`，调整缺素材回退测试。没有改动 HTTP 业务接口、Provider、任务状态机、检测版本、确认或导出规则；现有海报闭环仍是主任务。
