# 导出日期提醒修复

日期：2026-10-19，Asia/Shanghai。有限真实模型评估中，缺年份的合成图保留了原日期，模型 `uncertainties` 为空。前端会提示核实年份，但旧文字与 HTML 导出没有相同提醒，接收者离开核对台后容易遗漏这一限制。

新增回归先复现失败：`node --test --test-name-pattern="导出提醒接收者" tests/domain.test.mjs` 在缺少“年份待核实”提示的断言失败。随后在导出模板旁加入基于当前已核对时间字段的提醒，纯文本、复制结果与大字 HTML 均可带走；HTML 在关键信息下方显示提示。没有修改提取原文或自动补年份，规则提示与模型原始不确定项分开呈现。

提示沿用前端对四位年份的保守识别规则（1900–2099）。它不是日期有效性或完整性校验，不能证明活动日期、年份和时区正确；其他日期表达可能仍需要人工核实。当前字段为空时继续显示未知；核实补充年份后提示移除，修改使旧检测失效，重新检测和确认仍由原有门禁执行。

验证：`npm.cmd test` 21/21 通过，含 strict 编译；`npm.cmd run test:e2e` 20/20 通过。新浏览器用例实际生成草稿、运行 axe、逐项确认、下载文字与 HTML，核对提醒进入两份下载文件、原日期未补年、HTML 哈希与回执检测一致；另在浏览器打开实际导出内容并保存画面。已查看该画面，日期提醒位于事实字段下方。产物在 `.local/validation/recipient-date-20261019/`，不提交 Git。

结构影响：只修改 `src/domain.ts` 的受控导出与对应业务/浏览器回归。HTTP、任务状态、字段契约、Provider、前端交互、依赖和存储未修改；不用更多模型请求验证确定性的导出行为。旧进程不会重载领域模块，新预览单独启动，保留先前演示进程的内存会话。本修复不代表真实用户测试或模型质量全面达标。
