## 执行与判定

1. 固定材料与先验 → verify：Commons SHA-1、原图 SHA-256、尺寸 / 签名和实际解码，不向模型发送网页标题或先验。
2. 最多 1 次 `step-5-preview` / `poster-extract-v3` 请求、0 重试，90,000 ms、4,096 输出 tokens → verify：原始与应用字段分别评分，记录实际请求与可得 usage。成功、超时、失败、截断或发现编造 / 遗漏 / 差异均结束本批；请求上限不是人民币费用上限。
3. 原图对照和错误复查 → verify：原报告与先验不改写，另列审阅与未验证项；只在实际缺陷需要时修改产品，按节点提交。

这是一张来源方已处理的实拍海报，不能替代自然失焦、运动模糊、代表性材料或用户效果验证。读屏检查亦未开展：本机有 Windows 讲述人，但原生工具初始化返回“failed to write kernel assets: 系统找不到指定的路径。 (os error 3)”，没有实际朗读观察，不将 DOM 或自动 axe 当作读屏通过。

## 实际模型失败

## 同图参数对照：完整输出仍有语义错误

首批关闭后先查阅[官方推理档位说明](https://platform.stepfun.com/cookbook/step-5-reasoning)，再声明追加最多 1 次、本目标轮总计最多 2 次、自动重试 0。只将 `reasoning_effort` 从未指定改为 `low`，模型、图片、先验、提示词 v3、90 秒与 4,096 输出上限均不变；计划和报告在 `effort-low/`。官方示例使用 `/v1`；本次实测的 Step Plan 接口接受该请求，不能仅凭示例假定兼容。

记录提交 `1deaeaf`；实际 1 次、0 重试，40,451 ms、HTTP 200、`stop`，输入 1,150 + 输出 3,278 = **4,428 tokens**。原始与应用结果计数相同：已知匹配 0、已知差异 2、应未知却填值 1、未知保留 1。保留原评分，另写语义审阅：

- 名称使用 `PORTO`，把可见城市文字当作活动名；“应未知却填值”指字段角色错误，并非捏造字母。
- 时间含日期和时刻，但混入地点名称；地点只留 `CAIS DE GAIA`，遗漏图上的城市与另一地点。这两项不只是空白或标点差异。
- 报名方式保持未知，未把未标用途的域名当报名入口；时间没有补写年份。
- 概述补出无法从模糊区域核实的活动名称 / 类型与站点；图像说明没有提及大块模糊区域。未建立全文、翻译或完整描述准确率。

本轮累计 **2 次真实请求、0 自动重试、9,669 tokens**，没有第三次。两次为同一张图，不是两个独立样本；低档位这一次完整返回不能证明其因果效果、最优配置或质量更高。本机 `.env`、默认推理档位和输出上限未改。

## 提示词 v4：有针对性的约束，效果待实测

失败暴露的是语义角色与版面分组问题：逐字引用能通过一致性校验，仍可能把城市当活动名或把地点放进时间。本轮将提示词升级为 `poster-extract-v4`：区分活动名与城市 / 机构 / 域名，按版面组块保留换行，避免交错混入字段，地点保留可读层级与并列项，概述不从域名或场景补活动名，描述说明模糊与可读范围。规则不包含本例的专有地名，没有硬编码清除城市字段。
