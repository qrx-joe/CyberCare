# 语音与截图：修订和异常流程补强

日期：2026-10-22（Asia/Shanghai）。接续 [首版实现](multimodal-20261022.md)，本节点只处理现有两条链路的核对与异常行为，不增加模型调用、依赖、部署或用户效果承诺。

1. 复现具体失败 → verify：语音修订后的摘要差异缺提示；取消后旧 processing 响应覆盖页面；删除 500 错误被误认为成功。
2. 最小修复 → verify：同一组业务与浏览器回归由失败转为通过，保留原始识别与既有页面文案修改。
3. 失败路径与回归 → verify：确认响应丢失、保存失败、重新读取、404 清空；截图敏感/模糊场景；类型、构建、业务与全量浏览器。

## 已复现与修复

| 触发 | 修改前证据 | 修改后行为 |
|---|---|---|
| 全文把“市立活动室”更正为“示例活动室”，摘要仍有旧地点 | 新业务测试失败：`audioReviewHints` 为 undefined；浏览器没有对应差异提示 | 未保存草稿即时提示，已保存版本的 API、文字与 JSON 导出保留相同提示；同步修正摘要后消失 |
| 先取消，再返回之前取得的 processing 快照 | 新浏览器用例实际读到“正在处理” | 写操作使先前读取失效，旧快照不能覆盖取消、保存或确认结果 |
| 删除接口 HTTP 500，消息为“内部处理失败，请重试或删除任务” | 新浏览器用例读到“已清空本页资料并删除可访问的临时任务”，服务端任务仍可访问 | 仅 HTTP 404 视为已不存在；其他失败保留待删除 ID，提示删除未确认，再次删除可完成 |
| 确认已写入但响应丢失；保存响应失败；任务被服务端删除 | 补充浏览器回归 | 先只读恢复状态，恢复前禁用确认/导出；同版本的未保存文字不被覆盖；404 清空并允许重新开始，不自动重建任务 |

`audioReviewHints` 只比较初次转写中已有的关键事项与当前全文、摘要。仅归一 NFC 和布局空白，不把文本当正则，不自动改写摘要，不认定任一版本正确。它不能发现所有语义差异，也不能修复 ASR 误识别；仍须回听和人工核对。

## 截图边界补证据

在隔离的替代 Provider 服务中，故意返回“risk=normal，但要求填写验证码并支付”的结果：服务端将步骤清空、风险改为 sensitive；页面不给步骤、不允许继续，直接调用继续 API 也返回 `SENSITIVE_STEP`。这只证明确定性拦截路径，不证明真实模型能识别所有敏感页面。

另返回 uncertain 同时带有一步建议的矛盾结果：服务端清空步骤，页面要求暂停，用户确认后只能通过新截图继续。已有请求预算、同会话和截图哈希检查保留。以上替代请求没有访问真实供应商。

## 结构影响

- 新增 `src/audio-review.ts`：不接触 DOM、网络或密钥的纯文字对照，服务端与前端共用。
- `contracts.ts` / `assistance.ts`：可选的派生提示、同版本 API 和文字导出；没有改变确认输入协议或存储原文。
- `server.ts`：新增上述纯模块的静态资源映射。
- `web/assistance.ts`：写入与读取顺序、状态恢复、准确判断删除结果，以及草稿提示。
- `web/index.html`：仅为语音摘要新增提示区和读屏关联；保留原有未提交文案修改。
- `tests/assistance.test.mjs`、`browser/assistance-hardening.spec.mjs`、`browser/assistance-upload.spec.mjs` 和对应替代 Provider：复现、回归与边界场景。

原海报领域、axe 门禁、真实 Provider 协议、音频编码和任务到期规则没有修改。
