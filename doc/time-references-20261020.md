# 区分活动时间与截止时间

日期：2026-10-20（Asia/Shanghai）。承接[单图档位对照](effort-comparison-20261020.md)与[显式摘录](manual-excerpt-20261020.md)。本节点解决分散时间缺少独立表示的问题；不以放宽原文匹配、自动拼接或提高推理预算代替来源与用途核对。

## 最小兼容设计与完成标准

在模型提取中增加可选 `timeReferences`，最多 8 条，每条有用途 `kind`、逐字时间 `value` 和独立原文 `evidence`。用途为活动日期 / 时段、报名截止、提交截止、用途待核实。每条值和依据须分别连续定位到本条原文；用途仍是待人工核对的识别建议。旧模型、合成 / 人工输入没有该属性时保留旧行为与旧产物。

页面提供折叠的分类与勾选界面，由操作者更正用途，明确将选中项写入空白时间草稿。选择本身不保存，待写入选择期间不能检测 / 确认；写入后仍须填写依据、保存、重测与逐项确认。已有时间内容不覆盖，超过原 500 字符限制不截断；正文未保存、建议已不在正文、任务过期或状态变化时不能写入。

最终仍通过既有四字段编辑路径保存用途标注后的时间文字，变更、回执、纯文本与 HTML 从同一时间字段取得内容。没有新 HTTP 路由、编辑协议、持久化、依赖或发布动作；这是既有提取数据的可选扩展，模块职责和旧客户端路径保持一致。Provider 升级 v5：`facts.time` 表达活动时间，分散或不同用途的时间各自进入候选条目，不能把截止时间强塞为活动开始。

1. 契约与来源校验 → verify：旧输入不新增字段；分散候选独立定位，伪造 / 拼接项拒绝，未知用途不升级，长度 / 条数 / 类型边界明确。
2. 页面与导出闭环 → verify：显式选择 / 分类、草稿保护、修改失效、来源变更 / 到期、键盘与窄屏、保存记录和实际下载哈希。
3. 干净构建与有限真实复查 → verify：本节点请求上限 1、重试 0，90 秒、4,096 输出 tokens，显式 `low`；失败、截断或关键差异即结束。请求数不是人民币费用上限，真实请求不由测试自动执行。
