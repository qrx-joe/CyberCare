## 2. 项目结构与规模

- 技术栈：Node.js 24 + TypeScript strict 本地单体，无前端框架和数据库。生产依赖 4 个（zod、axe-core、playwright-core、image-size），版本已固定。
- 源码约 1,900 行，按 `contracts / domain / service / provider / audit / server / web` 分层，和 AGENTS.md 约定的职责一致。
- 测试：13 个业务测试文件，22 个浏览器 spec 文件。
- 文档：`doc/` 下 77 份，约 708 KB、4,300 余行，体量是源码的数倍。
- 提交：共 113 次，其中 `docs:` 76 次、`feat:` 17 次、`fix:` 13 次。10/20 当天 73 次，最近 5 次全是文档。
- 敏感文件：`.env`、`.local/`、`dist/`、`test-results/` 都已忽略，没有被版本库跟踪。

## 3. 优势

1. 视觉完成度高。首页品牌、大标题、角色和主按钮层次清楚，像真实产品。
2. 核心交互有说服力。核对页左边是可放大的原图，右边每个字段都给出"提取依据"。缺失的报名方式明确保留为未知，并提示去问活动方，不会补写。

4. 工程边界清楚。服务只监听本机，有来源校验和会话归属，任务 30 分钟过期，修改后旧检测失效，页面不接触密钥。

## 6. 截止前建议（按优先级）

1. 解决仓库访问：决定公开仓库还是给评委授权。公开前先扫描 Git 历史中的密钥与个人信息，再推送本地未推送的提交。按现有规则读取，不要求公网部署应用。
2. 准备一段真实 StepFun 识别的录屏，作为路演主线，同时准备合成样例兜底。发请求前先声明本批上限（建议 1–2 次）和停止条件。
3. 冻结功能，不再新增节点记录。
4. 精简演示界面上的免责文案，局限集中放到 PPT 的一页里。
5. 改 README 开头：用一屏说清是什么、怎么运行、验证了什么、还没验证什么，历史记录移到单独文件。
6. 跑一次 `npm.cmd run test:e2e`，通过后冻结候选版本。
7. 核实角色素材授权，确认前不用在对外海报和 PPT 里。
8. 按 4 分钟真人计时完整排练一次，提前定好演示路径。
