# 相对日期提醒修复

日期：2026-10-19，Asia/Shanghai。边界视觉评估中，模型忠实保留了“明天 14:00”，没有换算日期。检查人工核对和接收者导出时发现：旧规则只检查年份，“2026 年 10 月，明天 14:00”因含年份而不再提示，接收者仍不知道参照日期。

## 复现与修改

修复前，定向业务回归因导出缺少“相对日期待核实”失败；定向浏览器回归确认 `#guidance-time` 为 hidden。测试材料是开发者原创合成输入，不是真实活动或用户反馈。

页面和受控导出现在先检查常见相对表述，再检查年份。即使含年份，“今天、明天、后天、今晚、明晚、本周、这周、下周、本月、下月”仍提示核实具体日期及其参照日期，提醒不要按阅读当天推算。允许经核对后保留原文，提醒随产物带走，不强迫补一个未知日期。提醒是规则导出的核对建议，不回写或冒充模型原始不确定项。

保留用户材料的原值及初次提取；核实并修改为具体日期后提醒移除，仍须重新检测与确认。本改动不是时间解析器，不证明日历有效性，也不覆盖全部相对表达、时区和缺信息情形；提醒不替代人工核对。

## 验证与结构影响

`npm test` 25/25 通过，含 strict 编译；`npm run test:e2e` 21/21 通过。新增业务回归覆盖无年份、含年份的“明天”和“下周”，检查原值不变、补充具体日期后提醒移除、提取原文仍保留。新增浏览器回归实际生成、检测、确认和下载 HTML，检查提示在核对页与导出中出现、时间未自动改写、文件哈希与回执检测一致。

实际修改 `src/domain.ts` 的导出提醒、`src/web/app.ts` 的核对提示，以及对应业务和浏览器回归。HTTP、任务状态、Provider、模型提示词、字段契约、依赖与存储未修改。模型本批请求在修复前已结束；修复使用确定性本地回归，没有追加请求。旧展示与源码 ZIP 保留其冻结版本，不能用其旧测试数量代替当前新增回归记录。
