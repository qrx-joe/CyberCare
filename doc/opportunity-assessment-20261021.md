# 机会决策评估：用 product-opportunity-decision 评判本项目

评估日期：2026-10-21（Asia/Shanghai）。评估对象：`main` 分支 `908ce59`。评估框架：`D:\code\option-skill` 的 product-opportunity-decision skill——证据阶梯 E0–E4（猜测 → 口头表态 → 具体场景+已发生代价 → 重复绕路/投入 → 付费/采用），E2 为继续的最低门槛，按证据而非总分分流。

## 结论

**分流：`继续调研`；机会证据置信度：`低`。**

核心项（用户 / 场景 / 已发生代价）没有一项从真实目标用户处采集到 E2 证据，凑不出痛点标准句式，因此本评估**不打分**（skill 规则：无证据的维度填未知不给分；证据不足时不输出一排"未知"凑数，更不允许总分立项）。

不判 `淘汰`：关键项是"尚未采集"，不是"经追问被证伪或明确不可建立"；且类别级证据（W3C 无障碍体系、Be My Eyes / Project Sidewalk 等产品的真实存在与规模）支持问题域本身成立。竞品存在证明**类别**有需求，不证明**本项目**能赢——这是两条要分开的判断。

## 判定路径：为什么停在采集阶段

痛点标准句式：`[用户] 在 [场景] 中想达成 [目标]，但因 [阻碍]，产生 [代价]。` 两侧尝试构造：

- **操作者侧**：`[公益内容制作/核对者] 在 [制作/转发公益海报] 时想达成 [让读屏或大字阅读者获取关键信息]，但因 [？]，产生 [？]。`——用户是暂定假设（[MVP 方案](mvp-plan-20261022.md)自认"本轮实现假设，尚未通过访谈验证"），场景无近期实例，代价无任何记录。
- **接收者侧**：`[读屏/大字阅读用户] 在 [遇到只有图片的活动海报] 时想达成 [知道时间地点报名]，但因 [无文字替代]，产生 [错过活动/找人代读/放弃参与]。`——句式完整，但支撑它的是研究报告的类别级归纳（二手检索，E1），不是本项目从具体用户处采集的"可复述的最近场景"。类别成立 ≠ 本项目目标人群的 E2。

两侧均低于 E2 → 按 skill 走证据采集（Mode 1），不进入评分分流（Mode 2）。

## 缺失证据

- **操作者侧全部低于 E2**：人群是假设、无近期场景实例、无已发生代价（时间/返工/组织影响均无记录）。
- **接收者侧低于 E2**：有类别级问题陈述，无可复述的近期事件与具体代价。
- **行动信号为零**：无报名、无机构接触、无重复绕路记录、无采用意向。

## 两轮定向问题（问真实目标用户，不是问构建者）

最危险缺失假设 = H-01 操作者侧（产品是给操作者用的工具，接收者是受益方）。构建者本人无法代答这些问题——这正是两轮访谈无法在项目内部完成、必须外采的原因。

第 1 轮（冲用户 + 场景 + 代价）：

1. 最近一次需要把海报/通知做成别人能读的文字版本，是什么时候？为谁做、什么活动？
2. 当时怎么做的？卡在哪一步？花了多长时间？
3. 最后交付的东西对方能用吗？有没有返工，或干脆没做？

第 2 轮（第 1 轮有用户有场景、缺代价/频率时）：

1. 这类事多久一次？没做或做慢，谁受了什么影响？
2. 现在用什么凑合（人工读图、找人问、OCR）？每次多花多少时间？

接收者侧（可并行）：最近一次因为图片海报看不清而错过活动或找人帮忙，是什么时候？当时想干什么？最后怎么解决、花了什么代价？

**停止条件**：任一侧拿到 ≥1 个"具体近期事件 + 已发生代价"即达 E2，停止访谈进入打分分流。届时按分流表预判：行动信号未观察到 → `内容验证`；若操作者已展示重复人工转写等绕路行为（E3）→ `服务或模板验证`，现有本地 MVP 恰好可作受控人工交付的载体。

## 最小外部取证动作（不需要体验者配合）

- **假设**：目标人群中存在"因图片海报信息不可得而已付出代价"的可复述事件。
- **动作 A（接收者侧）**：在视障/低视力社群公开内容（贴吧、知乎、小红书"信息无障碍"话题等）收集 10 条"图片海报看不了 / 错过报名 / 找人代读"原话，做事件回溯归类。
- **动作 B（操作者侧）**：找 2–3 个公益组织内容岗做 20 分钟事件回溯，或先检索其公开分享中的相关吐槽。
- **时限**：1–2 周。
- **通过阈值**：≥2 个独立来源（不同用户、不同场合）各自给出具体近期事件 + 已发生代价 → 升 E2，重新进入打分分流。
- **不通过**：10 条多为泛泛表态、举不出事件 → 维持 `继续调研` 并考虑收窄人群；若明确"没人需要自己做无障碍版本"且拒绝收窄 → 进入淘汰讨论。
- **失败后动作**：收窄或停止，不以增加角色动画、功能节点或文档记录替代证据。

## Profile 与平台边界

当前定位为**外部产品**。本轮 MVP 是单边工具（操作者使用、接收者受益，无跨边网络效应），不触发平台 fail-fast。

注意：研究报告的长期愿景"公益任务操作系统"（任务市场 + 微任务验证网络）是**平台型**。若赛后往该方向推进，按 skill 必须拆成单边工具并作为**新机会**重新定义目标用户、重新取证，不得沿用本轮任何假设——本轮证据（为零的用户证据）本来就不够，更不能平移。

## 与赛事进度的关系

10/22 演示是独立的执行承诺，机会评估不否决参赛——两者证据线要分开讲：演示评"做出了什么"，机会评"是否有人需要"。昨日的[参赛完成度评估](project-assessment-20261021.md)指出的短板（缺真实用户证据、默认演示不出现 AI）与本结论同源。若赛后继续投入产品化，第一个动作应是上文的采证实验。skill 的"不在行动 + 付费证据前推荐做产品"映射到公益场景：**不在有"接收者实际使用 + 需求方采用意向"证据前，扩成产品或平台**。
